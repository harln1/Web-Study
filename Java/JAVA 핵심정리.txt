1. 클래스 구성요소
필드, 메소드, 생성자
2. 클래스 왜씀?
객체 만들라고. -> 객체가 뭘 할수 있는지 정의
3. 객체 어케만듬?
어쩌고 = new 클래스명()
4. static은 뭔데?
객체가 못 가져가는 "사장님꺼"
클래스 = 채용공고
5. 객체마다 "필드"의 값이 다를 수 있다!!!!
성별  통장잔고  여드름개수
static은 ?? -> 인간 - 생명수 : 1개
6. 생성자
객체가 만들어 지자마자 실행되는 것
생성자가 없는 객체는 "없다"
생성자 안만들면?? -> 컴퓨터가 자동으로 "기본 생성자" 만듦
                                 ------- -> 클래스() 괄호안에 아무것도 X
7. 생성자 해석법
클래스 객체명 = new 클래스()
                 ______ 이거보면 됨
                 얘랑 똑같이 생긴놈 찾아가면 됨 ( 없으면? 에러 )
8. Static 정적인
main메소드 실행전, 클래스에 고정시키는 역할
객체들이 공유하는 함수, 필드 등을 만드는데 사용
클래스이름.메소드() 로 사용하는게 정석
객체이름.메소드()도 실행이 되긴하는데, 경고 뜸.
★ 객체가 가져갈수 없다. 그리면 안됨!!!!
9. 필드의 초기화
static 필드는 즉시 실행
일반 필드는 생성자가 실행되자마자 초기화 진행
끝난 후, 생성자 안쪽 실행
★ 상속관계일경우, 부모님 생성자 끝내고, 내꺼 필드 초기화 후
   내꺼 생성자 실행
--------------------------------------------
10. 상속 -> extends
부모클래스(super) 가 자식클래스(sub)에게 아래를 상속해줌
 = 필드와 메소드 / 단, private, static, 생성자 제외
반드시 자식은 부모님을 1회 보고 와야 한다!!!

11. 자식의 생성자
택1. this / super
this -> 내꺼 생성자 실행
super -> 부모 생성자 실행
- 둘다 반드시 첫 줄에만 사용해야 함!!!
- 둘다 안쓰면 "super();" 자동으로 실행된다

12. 오버로드 / 오버라이드
- 오버로드(Overload) = 오버로딩(Overloading)
  같은 메소드 이름 + 다른 매개변수 => 이름 여러번 사용 가능
  A()  A(int x) A(double x) A(int x, int y)
  C, Python 사용 불가능

- 오버라이드(Override) = 오버라이딩(Overriding)
  반드시 상속에서만 사용할 수 있다!!!
  부모님이 준 "메소드"를 내맘대로 "재정의" 하는 것
  단, super.메소드명()으로 부모님꺼 사용 가능
  오버라이드를 안하면, 부모님이 주신 그대로 사용!!

13. 왔다리 갔다리 규칙 순서
- 클래스 객체명 = new 클래스(); 에서 ()형태를 보고 찾아가기
- 만약 없으면 기본 생성자 있다고 치고 확인
- 1순위 부모님 보고오기 ( 명시 안됬으면 super() 생략 )
- 2순위 내꺼 필드 세팅하기
- 3순위 생성자 안쪽 실행하기
